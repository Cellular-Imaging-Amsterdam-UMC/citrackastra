A headless workflow for local runs and Bilayers/BIOMERO.

Install locally

create_env.cmd
install_cuda.cmd
.venv\Scripts\python tools\download_models.py
.venv\Scripts\python tools\prepare_publicdata.py
.venv\Scripts\python wrapper.py --local --infolder publicdata/plates \
  --outfolder outputfolder --device cuda --model general_2d

Setup requires uv and creates Python 3.11. CUDA setup installs matching PyTorch 2.11.0 and torchvision 0.26.0 wheels with CUDA 12.6. Use --device cpu for CPU inference. Run install_sam2.cmd before selecting the optional SAM2 model.

Input contract

Use NGFF 0.4 / Zarr v2 directories with explicit t/y/x axes, optional c/z, positive spatial scales and physical spatial units. The root must declare a plate and wells with listed image fields. Each field needs at least two frames, Z absent or singleton, and instance labels on the same grid. Labels must match image dimensions, transforms and units. Channel numbers are one-based. Calibration must be in NGFF; an OME-XML file alone is insufficient for this adapter.

Only HCS plates with 2D time series are accepted. Standalone images, static fields and volumes are rejected; nothing is projected. Use CISegmentation outputs with --labels labels_cells or another label group. Source stores are read-only. Materialize labels-only overlays with corresponding source pixels before use.

Output semantics

Each source publishes a result directory with its copied OME-Zarr, tracking.sqlite, fields.csv, tracks.csv, observations.csv, links.csv and provenance.json. Trajectory labels live under labels/<source_name>_tracks. Optional tracking_movie.mp4, spacetime_movie.mp4 and movie.json contain sequential Divisualisation spacetime segments per field and label set. The vertical display axis is time, not physical Z; no independent error scoring is implied. Original pixels and labels are preserved. Existing destinations cannot be overwritten. Failures retain a hidden partial directory and FAILED.json.

Join using field_id and track_id. IDs identify CTC tracklets: gaps and divisions start new segments. parent_kind distinguishes gap continuation from division. Observations retain original instance IDs. Coordinates apply ordered transforms in micrometers; speed uses micrometers per second with calibrated time, otherwise per frame. Singleton speeds are NULL. Inference uses the original pixel grid; output calibration does not resample anisotropic voxels.

Bilayers and BIOMERO

config.yaml follows the CISegmentation descriptor pattern. python bilayers_cli.py validate checks the descriptor; generate prints its command. Stage images at /data/in, outputs at /data/out and cached models at /opt/models. The descriptor image is a planned release target.

Result stores live one level inside each source result directory. The integration must discover stores recursively and attach their SQLite/CSV companions. Verify this mapping in your installed BIOMERO version. Production OMERO/Slurm roundtrip validation has not been performed.

Divisualisation movie

Install install_movie.cmd and add --movie true. This uses the actual Divisualisation SpacetimeLift renderer, with a conventional 2D tracking MP4 and a spacetime MP4 per plate. Plate fields and label sets play as sequential segments. Windows uses a hidden native OpenGL context; unattended Linux uses the prepared Xvfb/Mesa movie runtime.

Separate model images

Dockerfile prepares the headless CUDA runtime. Dockerfile.models packages only the cached models and licenses; Dockerfile.with-models combines them later. Alternatively bind-mount the cache at /opt/models. Dockerfile.movie adds the optional unattended movie runtime. No Docker build or Docker Hub publication has been performed.
